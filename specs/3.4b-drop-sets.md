# 3.4b – Drop sets

Issue: jjerner/FitTracker#44 (label `sql`). Split out of 3.4 (#20, `specs/3.4-set-types.md`), which shipped warm-up sets (`0017_warmup_sets.sql`).

## Goal

The user can log a drop set: one set where the weight goes down partway through, for example 50 kg × 2 → 40 × 3 → 30 × 3. It counts as **1 set**, but every step is saved and shown.

## Today

- `workout_log_sets` has one row per ticked set. `set_type` is `'normal' | 'warmup'`, enforced by a check constraint (0017). Rows are sorted by `set_number`.
- `records.ts`: `workingSets` leaves out warm-ups. `setLabels` gives W, W, 1, 2. `matchingSet` matches warm-ups with warm-ups and everything else with everything else, by position.
- Active workout (`active.tsx`): tapping the Set badge on an unticked strength row switches 1 ↔ W. The type is saved when the row is ticked (`addSet`), and also with the offline queue (`pendingSets.ts`).
- Summary (`log/[logId].tsx`): "Sets" = every row. Volume = weight × reps over `workingSets`. The edit popup has Normal / Warm-up chips.
- Weekly sets per muscle (`progress.ts` `getMuscleSetRows`): counts every row (`workout_log_sets(id)`).
- Two places force the type to two values: `pendingSets.ts:111` and `active.tsx:154` (`=== 'warmup' ? 'warmup' : 'normal'`).

## Proposal (smallest version)

**Each drop step is its own row with `set_type = 'drop'`. It belongs to the set just above it.** The table stays the same; only the allowed values change.

So 50 × 2 → 40 × 3 → 30 × 3 is saved as three rows: `normal 50×2`, `drop 40×3`, `drop 30×3`.

Why rows and not a list of steps inside one row: ticking, un-ticking, the offline queue, "Previous", volume and records all work on rows already. A list inside one row would need new inputs, a new column format, and changes to the offline queue, volume and records.

- **Entering it (active workout):** the Set badge now goes through three types: 1 → W → D → 1. A D row is a drop step. You type its kg and reps and tick it like any other row. D is not offered on the first row of an exercise, because there is no set above it to belong to. Cardio stays the same (the badge can't be tapped).
- **Numbering:** D rows get no number, like W rows: `W, 1, D, D, 2`. "Previous" and the grey suggestions match a D row with last time's D row in the same position.
- **Counting as 1 set:** the summary "Sets" number and weekly sets per muscle leave D rows out.
- **Volume:** every step counts (weight × reps of each row), so there is no change.
- **Records (PRs, est. 1RM, chart, tracked stats):** every step counts like a normal set, so there is no change. The first step is usually the heaviest, so the steps rarely matter.
- **History and summary:** D rows show as `↘ Drop: 40 kg × 3` under the set they belong to. The summary edit popup gets a third chip, Drop.

## Needs from the user

- Paste `supabase/migrations/0021_drop_sets.sql` into the Supabase SQL editor **before** `eas update`. If you don't, a D step is rejected by the old check. The offline queue then treats that as "can never be saved" (error code `23…`) and **deletes the set from the phone**, so it is lost.
- No new APK build. This ships as JS via `eas update`.
- Answers to the open questions below.

## Open questions

1. **How to store it:** one row per step (this spec, smallest), or one row holding a list of steps? The only real difference is that with rows, an un-ticked and re-ticked set moves to the end, the same as warm-ups today (see Out of scope). **Default: one row per step.**
2. **Records:** should drop steps count for PRs and est. 1RM? **Default: yes**, like any working set. The alternative is to count only the first step.
3. **Volume:** should every step count? **Default: yes**, all steps.
4. **Label:** D with no number (`1, D, D, 2`), or something else, such as `1, 1↘, 1↘, 2`? **Default: D, matching W.**

## Out of scope

- A drop set entered as a single row with several steps inside it (cut: needs new inputs and a new data format).
- Keeping order after un-tick and re-tick. A re-ticked set gets a new `set_number` and moves to the end, as warm-ups do today. You can fix it in the summary edit popup.
- Blocking or fixing a D row with no set above it, for example after deleting its set. It counts as 0 sets but still adds to volume and records.
- Drop sets on cardio, drop-set targets in routines, and auto-suggested drop weights (e.g. −20%).
- Pausing the rest timer between steps. Each tick restarts the timer, as today, so the last step sets it.
- "Delete set D?" / "Edit set D" wording in the alerts. It reads fine as it is.
- Leaving warm-ups out of weekly sets per muscle (separate from this item).
