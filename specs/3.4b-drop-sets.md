# 3.4b – Drop sets

Issue: jjerner/FitTracker#44 (label `sql`). Follows 3.4 warm-up sets (`0017_warmup_sets.sql`). This replaces the earlier draft of this spec. The Decisions on the issue are final.

## Goal

The user can log a drop set, for example 80 × 8 ↓ 60 × 6 ↓ 40 × 6. Each step is saved as its own row and adds to volume. The whole drop set counts as **one set**, and only its first step counts for records.

## Rules (from the Decisions, plus the edge cases settled here)

- **Storage:** each drop step is a `workout_log_sets` row with `set_type = 'drop'`. Its drop set starts at the nearest non-drop row above it. Saving, the offline queue, undo and CSV export use the code paths they use today.
- **Badge cycle (unticked strength rows):** 1 → W → ↓ → 1. ↓ is skipped when the row is the first one, or when the row above is a W. Cardio badges stay untappable.
- **Labels:** ↓ rows get no number. `W, 1, ↓, ↓, 2`.
- **Counting:** "Sets" on the summary and the weekly sets per muscle leave ↓ rows out. Warm-ups still count, as they do today.
- **Volume** (summary volume, "vs last time", `setsVolume`, Best volume, the volume record) counts every step and leaves warm-ups out.
- **Records** (heaviest, est. 1RM, rep-count bests, tracked stats, the chart, the 🏆 in the workout and on the summary) count `normal` rows only. That leaves out warm-ups and ↓ rows, so only the first step of a drop set counts.
- **Rest timer:** ticking a row with a ↓ row right below it starts no rest. Ticking the last step starts rest as usual.
- **History lines** (summary and exercise page): a set and its drop steps go on one line, `Set 1: 80 kg × 8 ↓ 60 kg × 6 ↓ 40 kg × 6`.
- **"Previous" / grey suggestions:** a ↓ row matches the step in the same position under last time's matching set. So the 2nd ↓ under set 1 matches the 2nd ↓ under last time's set 1. If there is no such step, it shows `—`. Normal rows match last time's normal rows by position and skip drop steps.
- **Edge case, orphan ↓** (the row above was deleted, changed to W, or un-ticked and re-ticked so it moved to the end): nothing is fixed automatically. The ↓ stays a ↓. It adds to volume but not to the Sets count or records, and on history lines it joins the line above it. If it is the very first row, it gets its own line. The user can fix it by un-ticking it in the workout, or with the summary edit popup.
- **CSV:** the "Warm-up" yes/no column becomes "Type" and holds the raw `set_type` (`normal` / `warmup` / `drop`).

## UX/UI

**Flow**
- Workout: add a row → tap its Set badge until it shows ↓ (1 → W → ↓ → 1) → type kg and reps → tick. Tick the first step and each ↓ in order: no rest bar until the last step is ticked.
- Summary: the drop set is one line → tap one step → the edit popup opens with "Drop" selected → Save → back on the summary.
- Exercise page: the drop set is one line in the history list (not tappable, like today).

**Screens and parts.** Nothing new. Reused: the set row and Set badge in `active.tsx`, the `warmupText` style (amber), the summary set list, the edit popup with `Chips`, `formatSet`. Changed:
- **Set badge:** a third state, ↓. Same grey badge, same amber text as W, so W and ↓ read as "not a plain working set". Done rows show ↓ in amber too.
- **↓ rows sit tight under the row above** (`paddingTop: 0`, no indent, so the columns stay lined up). The ↓ glyph itself points back to the set it belongs to.
- **Previous column:** each row shows its own match (decided, see Open questions). A ↓ row shows its matching step, or `—`.
- **Summary set list:** one wrapping line per drop set. Each step is its own tap area (48 dp tall).

**States.** No new loading, empty or error states. Ticking a ↓ shows the same spinner in the tick box. Save errors and the offline queue work as today. A ↓ row with no match last time shows `—` in Previous and today's grey fallback in kg and reps.

**Words**
- Badge: `↓`. Labels in a list: `W, 1, ↓, ↓, 2`.
- TalkBack on the badge: label "Drop step" for ↓, "Set 1, working set" / "Set W, warm-up" as today. Hint names the next tap: "Tap to mark as warm-up" (on 1), "Tap to make it a drop step" (on W, when ↓ is allowed), "Tap to make it a working set" (on ↓, or on W when ↓ isn't allowed).
- Done-row label on a ↓ row reads "Drop step" to TalkBack.
- Summary line: `Set 1: 50 kg × 2 ↓ 40 kg × 3 ↓ 30 kg × 3 ✎`. A ↓ step is read as "Drop step, 40 kg × 3".
- Edit popup chips: `Normal`, `Warm-up`, `Drop`. Its title for a ↓ step stays "Edit set ↓" (see Out of scope).
- Exercise page: `Set 1: 50 kg × 2 ↓ 40 kg × 3 ↓ 30 kg × 3`.

**Wireframe: active workout (changed rows)**

## Acceptance criteria

- [ ] 0025 runs on the live database. Old workouts show the same labels, Sets, volume and records as before.
- [ ] Strength row 1: the badge goes 1 → W → 1. A row under a working set or a ↓ goes N → W → ↓ → N. A row under a W goes N → W → N. Cardio badges can't be tapped.
- [ ] Logging 50×2, ↓40×3, ↓30×3, then 45×5 shows `1, ↓, ↓, 2`.
- [ ] No rest bar after ticking 50×2 or 40×3. The rest bar starts after 30×3 and after 45×5.
- [ ] Summary: Sets = 2, Volume = 535. The line reads `Set 1: 50 kg × 2 ↓ 40 kg × 3 ↓ 30 kg × 3`, then `Set 2: 45 kg × 5`. Each step opens its own edit popup, and a ↓ step shows the "Drop" chip selected.
- [ ] Records ignore drop steps: a ↓ step heavier than every working set changes neither Heaviest weight nor est. 1RM nor the rep-count rows, but it does raise Best volume.
- [ ] Next workout: a ↓ row's "Previous" shows last time's step in the same position, and row 2 shows last time's set 2.
- [ ] The exercise page history shows the drop set on one line.
- [ ] Weekly sets per muscle adds 2 (not 4) for that exercise.
- [ ] The workouts CSV has a "Type" column, with `drop` on the steps.
- [ ] Offline: a ↓ step queued with no signal is still `drop` after it syncs. A queued set with no type goes out as `normal`.
- [ ] `npx tsc --noEmit`, `npx expo lint` and `npx jest` pass.

## Out of scope

- Drop sets planned in a routine, and automatic weight suggestions for drops (Decisions). Grey suggestions on ↓ rows use today's fallback (last time's step, then the routine target, then the last ticked row).
- Fixing orphan ↓ rows automatically, or blocking delete/W on a set that has ↓ rows under it.
- Keeping the order after un-tick and re-tick. A re-ticked row moves to the end, as it does today.
- Wording for ↓ in the delete and edit dialogs ("Delete set ↓?", "Edit set ↓"). It reads OK.
- Stopping a rest timer that is already running when a first step is ticked.
- Drop sets on cardio.
- Leaving warm-ups out of the Sets count and weekly sets per muscle. That is today's behaviour and a separate item.
