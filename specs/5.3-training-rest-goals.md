# 5.3 – Different goals on training vs rest days

Issue: jjerner/FitTracker#21 (label `sql`). HANDOVER.md → Proposed roadmap, section 5: "Different goals on training vs rest days. 🗄 | M". The roadmap has no more detail than that.

## Goal

Let the user set a second set of macro goals for rest days. On a day with a finished workout the app uses the normal goals; on any other day it uses the rest-day goals.

## Today

- `nutrition_goals` (migration `0002_food.sql`) has one row per user: `calories_kcal`, `protein_g`, `carbs_g`, `fat_g`, `fiber_g`. RLS lets the user select, insert and update their own row.
- `src/lib/foods.ts:615-652` `getNutritionGoals` / `upsertNutritionGoals` map that row to `NutritionGoals` (`src/types/domain.ts:62`).
- `src/hooks/useNutritionGoals.ts` wraps both in React Query (`['nutritionGoals', userId]`).
- `src/app/(tabs)/profile/goals.tsx`: three inputs (Protein, Carbs, Fat). Calories are worked out from them (P×4 + C×4 + F×9), not typed in.
- Goals are read in two places: Home's "Today's food" card (`home.tsx:36, 111-115`) and the Food diary top card (`food/index.tsx:58, 288-292`, for whatever date the diary shows).
- "Training day" can already be found with no new data: `useWorkoutDates()` (`src/hooks/useProgress.ts:79`) returns the local dates of **finished** workouts for the last 365 days. Home already loads it.

## Proposal (smallest version)

- **Storage:** add 4 nullable columns to the existing row: `rest_calories_kcal`, `rest_protein_g`, `rest_carbs_g`, `rest_fat_g`. All null = no rest-day goals, so the app works exactly like today. No new table, no change to the unique index or RLS.
- **Which day is a training day:** a day that has at least one finished workout (`useWorkoutDates` contains that date). Everything else is a rest day. No weekday schedule, no manual toggle (see open question 1).
- **Goals screen:** today's three inputs stay as the "training day" goals. Under them, a `Switch` "Different goals on rest days". When on, three more inputs (Protein, Carbs, Fat) with their own calculated kcal line. When off, saving clears the rest columns to null.
- **Home + Food diary:** pick the goals for the shown date with one small helper, and show a short "Training day" / "Rest day" label on the card, only when rest-day goals are set.

## Files to touch

- `supabase/migrations/0017_rest_day_goals.sql` (new): `alter table public.nutrition_goals add column rest_calories_kcal int, add column rest_protein_g numeric, add column rest_carbs_g numeric, add column rest_fat_g numeric;`
- `src/types/domain.ts`: add `rest: { caloriesKcal: number; proteinG: number; carbsG: number; fatG: number } | null` to `NutritionGoals`.
- `src/lib/foods.ts`:
  - `getNutritionGoals`: map the 4 columns into `rest` (null when `rest_calories_kcal` is null).
  - `upsertNutritionGoals`: write them (null when `rest` is null).
  - New pure helper `goalsForDay(goals: NutritionGoals, isTrainingDay: boolean): NutritionGoals`: returns `goals` on a training day or when `rest` is null, otherwise `goals` with calories/protein/carbs/fat swapped for the rest ones.
- `src/app/(tabs)/profile/goals.tsx`: the switch and the second set of inputs, as above. Add `rest: null` to `DEFAULT_GOALS`. Save is disabled if the switch is on and a rest input is not a number.
- `src/app/(tabs)/home.tsx`: `goalsForDay(goals, workoutDays.has(today))` (both already in the file) and pass the result to `CalorieRing` / `MacroBar`. Add the day-type label.
- `src/app/(tabs)/food/index.tsx`: call `useWorkoutDates()`, compute the goals for `date` the same way, pass them to the totals card. Invalidate `['workoutDates']` on focus, the same way Home does (`home.tsx:42-47`), so finishing a workout updates the diary.
- `src/lib/__tests__/goalsForDay.test.ts` (new): tests for the helper.

## Open questions

1. **How is a training day detected?** (a) a finished workout that day (proposed, no extra data, but in the morning before you train the app shows rest-day goals); (b) fixed training weekdays picked in settings (needs one more column, e.g. `training_weekdays int[]`); (c) a manual "Training day" toggle per day in the diary (needs a new table keyed by date). Or (a) plus counting a workout that is in progress?
2. **Which set is the "normal" one?** Proposed: today's goals become the training-day goals and the new set is for rest days. Or the other way round (today's = rest, new = training)?
3. **Macros or just calories?** Proposed: a full second set (protein, carbs, fat, and calories worked out from them, same as today). Or only a different calorie number, keeping macros the same?
4. **Show the day type?** Proposed: a small "Training day" / "Rest day" label on the Home and Food cards when rest goals are set. Or no label?
5. **Order vs 5.2 goal helper and 2.9 adaptive goal:** both would *write* goals. Should 5.3 ship first as planned (the helper and adaptive goal would then need to fill in, or leave alone, the rest-day set), or wait until those are decided?

## Out of scope

- Weekday schedules or per-day manual overrides (unless question 1 picks one).
- A separate fiber goal for rest days (`fiber_g` is not used in the UI).
- Burned calories or adding workout calories to the goal.
- 5.2 goal helper and 2.9 adaptive goal (this spec only stores and picks between two typed-in sets).
- Goal hit-streaks (4.4) or any change to the Progress screen.
