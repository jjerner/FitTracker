# 4.2 – Weekly sets per muscle group

Source: GitHub issue jjerner/FitTracker#14, HANDOVER.md → Proposed roadmap → section 4 ("Weekly sets per muscle group", M).

## Goal

A new card on the Progress tab shows, for each muscle group, how many sets the user logged this week and in each of the 3 weeks before it. Weeks start on Monday. This answers "am I training legs enough?"

## Design

- **Muscle group = `exercises.muscle_group`, used as it is.** The shared exercises use 6 groups: chest, back, legs, shoulders, arms, core (migrations 0004 and 0007). For custom exercises it is free text (`CreateExerciseForm`), so the value is trimmed and lowercased before grouping ("Chest " and "chest" count together). Strength exercises with no group go under "Other". Cardio exercises (`category = 'cardio'`) are left out.
- **What counts as a set:** every row in `workout_log_sets` belongs to a set that was ticked ✓. The count includes only completed workouts, the same rule `getWorkoutDates` uses. A workout belongs to the week its `started_at` falls in, using local time.
- **One exercise = one group, and every set counts fully.** Bench press counts for chest only, not for triceps.
- **Fetching:** one request on `workout_log_exercises`, built like `getExerciseHistory`: `exercises(muscle_group, category), workout_logs!inner(started_at, completed_at, user_id), workout_log_sets(id)`, filtered on user, completed, and `started_at >=` the Monday 3 weeks ago (local midnight sent as an ISO timestamp, so the A4 UTC-midnight issue doesn't apply). The request returns one row per exercise done, not one per set. That is about 100–200 rows for 4 weeks, far under Supabase's 1000-row limit.
- **Layout:** a table that looks like `NutritionAveragesCard`. There is one row per muscle group, sorted alphabetically with "Other" last. The 4 columns are "This wk" and the start dates of the 3 weeks before, e.g. "6/10" (`shortDate` of the Monday). A week with no sets shows `0`. If there are no strength sets in the 4 weeks, the card says "No strength sets logged in the last 4 weeks."
- **Later, roadmap 3.4 (set types):** when sets get a type, add `.neq('set_type', 'warmup')` on the nested sets (or filter them in the pure function). That is a one-line change and is not done now.

## Files to touch

- `src/lib/dateUtils.ts`: move `mondayOf(date)` and `addDays(date, days)` here from `home.tsx` without changing them, and export them.
- `src/app/(tabs)/home.tsx`: delete the two local functions and import them from `dateUtils`. Nothing else changes.
- `src/lib/progress.ts`
  - New `getMuscleSetRows(userId, sinceIso): Promise<{ startedAt: string; muscleGroup: string | null; category: string; setCount: number }[]>`. It runs the query above and sets `setCount = workout_log_sets.length`.
  - New pure `weeklyMuscleSets(rows, weekStarts: string[]): { group: string; counts: number[] }[]`. `weekStarts` is a list of Monday dates, newest first. It skips cardio, uses the trimmed lowercased group or `'other'`, finds the week of each row with `mondayOf(localDateOf(new Date(startedAt)))`, adds up `setCount`, and returns the groups sorted alphabetically with `other` last. Groups with 0 in every week are left out.
- `src/hooks/useProgress.ts`: new `useMuscleSets()`. Query key `['muscleSets', userId]`. It calls `getMuscleSetRows` from the Monday 3 weeks before this week.
- `src/app/(tabs)/progress.tsx`
  - New `MuscleSetsCard` placed after `WorkoutsCard`. It works out `weekStarts` (this Monday and the 3 before it, via `mondayOf`/`addDays`), calls `weeklyMuscleSets`, and draws the table with the existing `tableRow`/`tableLabel`/`tableHeader`/`tableCell` styles. Group names are shown with a capital first letter.
  - Add `queryClient.invalidateQueries({ queryKey: ['muscleSets'] })` to the existing `useFocusEffect`.

## Reuse

- `getExerciseHistory`'s `!inner` join pattern (`src/lib/workouts.ts`).
- `mondayOf`/`addDays`, which are moved from `home.tsx` and not rewritten. Also `localDateOf`, `todayLocalDate` and `shortDate` (already in `progress.tsx`).
- The table styles and the loading/empty pattern from `NutritionAveragesCard`.
- No migration, no new dependency, and no chart library work.

## Acceptance criteria

- [ ] The Progress tab shows a "Sets per muscle group" card with columns "This wk" and the 3 earlier Mondays (e.g. "6/10", "29/9", "22/9").
- [ ] A completed workout with 3 sets of Bench Press and 4 sets of Back Squat adds 3 to Chest and 4 to Legs in the week it was started.
- [ ] Cardio exercises are never counted. A strength exercise with no muscle group counts under "Other", which is the last row.
- [ ] A custom exercise with group "Chest " counts in the same row as the shared "chest" exercises.
- [ ] A workout that is still in progress is not counted. Once it is finished and the user returns to Progress, the card updates without a reload.
- [ ] A workout started on a Sunday evening (local time) counts in that week, not in the next one.
- [ ] With no strength sets in the 4 weeks, the card shows the empty message.
- [ ] The Home tab's week strip and streak still look and work the same after `mondayOf`/`addDays` are moved.
- [ ] `npx tsc --noEmit` and `npx expo lint` pass.

## Test plan

- Unit tests in `src/lib/__tests__/progress.test.ts` (Supabase is already mocked there):
  - `weeklyMuscleSets`: sets are added up per group and week; cardio is skipped; a null or empty group becomes `other`, which is sorted last; `" Chest"` and `"chest"` are merged; a row older than the oldest week start is ignored; a group with only zeros is left out.
  - `mondayOf`: a Sunday gives the Monday 6 days before, and a Monday gives itself.
- Web click-through with the test account from `.env.test.local`:
  1. Open Progress and check that the card shows, with the right numbers for what the test account has already logged (compare with the workout history).
  2. Start a workout with Bench Press (3 sets) and Running (1 entry). Go to Progress: the counts have not changed. Finish the workout and go back to Progress: Chest "This wk" has gone up by 3 and there is no cardio row.
  3. Create a custom exercise with group "Chest " and log 1 set: it adds to the Chest row. Create one with no group: an "Other" row appears last.
  4. Open Home: the week strip and streak are unchanged.
  5. Check the console for errors.
- Phone: nothing extra. The card is only a read-only query.

## Needs from the user

- None. No SQL and no APK build; it ships as JS via `eas update`.

## Open questions

1. **Muscle group detail:** "arms" covers both biceps and triceps, and "legs" covers quads, hamstrings, glutes and calves. Is the 6-group split OK for now, or should the finer `movement_pattern` (biceps / triceps / calves / ...) split those groups?
2. **Which weeks:** this spec shows this week plus the 3 before it, as a table. Is that what you want, or would you rather have a different number of weeks, or a bar chart?
3. **Compound lifts:** this spec counts each set fully for one group (bench press counts for chest only). Is that OK, or should secondary muscles count too (e.g. half a set for triceps)? Counting them would need a new data field and a migration.

## Out of scope

- Target ranges or advice (e.g. "10–20 sets per week").
- Leaving out warm-ups. That waits for roadmap 3.4 (see Design).
- Secondary muscles, or giving partial sets to other muscles.
- Tapping a group to see which exercises or workouts are behind the number.
- A range picker (`RangeTabs`) on this card.
- Sets still waiting in the offline queue (`pendingSets`). They count once they have synced.
- Editing the muscle group of existing exercises.

## Decisions (PM, 2026-10-18)

1. The existing **6 groups** (chest, back, legs, shoulders, arms, core) + "Other".
2. **Table, 4 weeks** (this week highlighted + 3 before, Monday start). Sketch approved: columns "3 wk ago / 2 wk / Last / This", footnote "Weeks start Monday. Finished workouts only."
3. Each set counts for the exercise's **main muscle only**.
