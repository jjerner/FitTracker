# 3.6 – Per-exercise rest time

Source: issue jjerner/FitTracker#19 (label `sql`), HANDOVER.md → Proposed roadmap 3.6 (and 5.1 / C4: the default rest setting is done, "per-exercise stays 3.6").

## Goal

A routine can set its own rest time for each exercise (e.g. 3:00 for squats, 1:00 for curls). When a set is ticked in a workout started from that routine, the rest timer uses that time; otherwise it uses the default rest from Profile, like today.

## Proposed approach (needs a yes, see Open questions)

Store the rest time on the routine row (`workout_template_exercises.rest_seconds`), next to the existing targets (sets / reps / kg). It travels with the `target` the active screen already looks up, so no new table, query or hook is needed. This is how Hevy does it. Exercises added mid-workout (not in the routine) use the default.

## Files to touch

- `supabase/migrations/0017_template_rest_seconds.sql` (new; next free number after 0016)
  ```sql
  -- Rest time per exercise in a routine (seconds). Null = use the app's default rest.
  alter table public.workout_template_exercises
    add column rest_seconds int check (rest_seconds > 0);
  ```
  RLS is unchanged (the table's existing "own templates" policy covers the new column).
- `src/types/domain.ts`: `WorkoutTemplateExercise` gets `restSeconds: number | null`.
- `src/lib/workouts.ts`
  - `mapTemplateRow`: `restSeconds: te.rest_seconds`.
  - `saveTemplate` insert: `rest_seconds: te.restSeconds`.
- `src/lib/programs.ts`: `routineExercises` returns `restSeconds: null` (built-in programs have no rest times).
- `src/app/(tabs)/workouts/[templateId].tsx`
  - `DraftExercise` gets `rest: string`; filled from `te.restSeconds?.toString() ?? ''`; new rows from the picker start with `rest: ''`.
  - `showTargets` also true when `te.restSeconds != null`.
  - A 4th `TargetInput` in the strength targets row: label `Rest (s)`, placeholder = the current default rest in seconds (from `useDefaultRest()`), so an empty box visibly means "default".
  - `draftToTemplateExercises`: `restSeconds` = `toNumberOrNull(e.rest)`, rounded; `null` when empty or `<= 0` (so a typed 0 never hits the DB check).
- `src/app/(tabs)/workouts/active.tsx`
  - In the `exercises.map`, pull the existing `template?.exercises.find(...)` into a `const target` and use it for both the `target` prop and the timer:
    `onSetDone={() => setRestEndsAt(Date.now() + (target?.restSeconds ?? defaultRest.seconds) * 1000)}`
  - `ExerciseCard` unchanged except: show the rest in `targetText` when set, e.g. `Target: 5 × 5 @ 100 kg · Rest 3:00` (reuse `formatDuration` from the same file).
- `src/lib/__tests__/programs.test.ts`: add `restSeconds: null` to the expected row.

## Reuse

## Open questions

1. Where does the override live?
   - **A (proposed, smallest):** per exercise **in a routine** (one column on `workout_template_exercises`). Same exercise can have different rest in different routines; ad-hoc workouts and mid-workout additions use the default. Like Hevy.
   - **B:** per exercise **for the user, everywhere** (new table `exercise_settings(user_id, exercise_id, rest_seconds)` with own-rows RLS like `tracked_exercises`, set from the exercise page or the active card). Works in every workout, incl. global catalog exercises, but adds a table, lib functions, a hook and a new UI spot. Like Strong.
   This spec is written for A; B would need a rewrite of "Files to touch".

## Out of scope

- Per-user override for all workouts (option B) and editing rest from the exercise page.
- Changing the rest time from inside an active workout (the ±15 buttons still adjust the running timer only).
- Rest for cardio exercises; rest per set; rest after supersets (3.7).
- Rest timer notification while the phone is locked (3.9).
- Showing rest times on built-in programs.

## Decisions (PM, 2026-10-18)

These override the proposal above where they differ.

1. **Option A: inside a routine** (column on `workout_template_exercises`). Workouts not started from a routine use the default.
2. **UI must make it clearly optional** — approved sketch: a separate **"+ Rest time"** link next to "+ Targets" (hidden until tapped). Without an override the exercise shows grey "Uses your default rest (1:30)". With one: the rest input plus "✕ Use default" to clear it (saves null). Active workout target line shows "🕐 Rest 3:00".
3. Input is **minutes + seconds in two boxes**: `[ 3 ] min [ 00 ] sec`, max 10:00, stored as seconds. Use one small shared component.
4. **Also change the Profile default rest setting** (Workouts sub-screen after S42) to the same min + sec boxes, replacing − / +. Build after S42, since S42 moves that setting.
5. Migration number assigned at build time.
