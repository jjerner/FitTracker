# 3.7 – Supersets

Issue: jjerner/FitTracker#32 (label `sql`). The Decisions on the issue are final; this spec only settles the edge cases they leave open.

## Goal

The user can pair two exercises as a superset, in a routine and in a running workout. Ticking a set on the first exercise starts no rest. Ticking a set on the second one starts that exercise's rest.

## Rules (Decisions + edge cases settled here)

- **Storage:** `superset_with_next boolean not null default false` on `workout_template_exercises` and `workout_log_exercises`. A row with the flag pairs with the row right below it (next `position`).
- **Pairs only.** One pure helper, `supersetRoles(flags)`, turns the flags into `'first' | 'second' | null` per card, top to bottom. A card right below a `'first'` card is `'second'`, and its own flag is ignored. A flag on the last card is ignored. Every screen uses this helper, so a stray flag can never make a group of 3.
- **"⛓ Superset with next"** shows on a card only when that card and the card below are both unpaired. So it is hidden on the last card, on both cards of a pair, and on a card whose next card already starts a pair.
- **"Unlink"** sits once per pair, in the frame header. It clears the first card's flag.
- **Removing a card** (routine editor, or workout card with no sets) also clears the flag on the card above it. If that card was the first of the pair, the pair breaks. Without this, the card above would quietly pair with the next card.
- **Routine editor ↑/↓:** moving a card clears the flags on the two cards that change places and on the card above them. Every pair the move touches breaks, and the user links again. The active workout has no reorder.
- **Swap**
  - No sets yet (swap in place): the flag stays on the row, so the pair stays. No code needed.
  - Sets already logged (today the new exercise is inserted below and the old one keeps its sets): the new exercise takes the old one's place in the pair, and the old one leaves the pair with its sets.
    - Old card is **first**: insert the new card right below it with `superset_with_next = true`, then clear the old card's flag. Result: `A · [A' + B]`.
    - Old card is **second**: insert the new card right after the first card (`afterPosition` = the first card's position). Result: `[X + A'] · A`.
- **Starting from a routine:** `startWorkout` copies `superset_with_next` with each exercise.
- **Rest timer:** `if (!isCardio && !pairedWithNext && types[index + 1] !== 'drop') onSetDone();`
  - On the first card of a pair, a tick never starts rest, whatever the drop sets are.
  - On the second card, the drop-set rule applies as today (no rest when a ↓ row is right below). Rest uses the second card's own rest time (`target.restSeconds` of that card, or the default). This is what happens today, because each card's `onSetDone` reads its own target.
  - A rest timer that is already running is left alone, as with drop sets.
- **Online only:** link, unlink, and the extra flag writes for swap and remove go straight to Supabase, like add/swap/remove exercise do today. If a write fails, the screen shows the usual "Could not …, check your connection" alert. The offline set queue (`pendingSets.ts`) is unchanged.

## UX/UI

**Flow**
- Routine: on the card, tap "⛓ Superset with next" → the card and the one below get one frame → Save Routine. Tap "Unlink" in the frame header to split them.
- Workout: the same links on the workout cards, saved at once. Tick a set on A: no rest bar. Tick a set on B: the rest bar starts with B's rest time.
- Summary: the same frame, with no Unlink.

**Parts.** One new shared component, `src/components/workouts/SupersetFrame.tsx`, used by 3 screens. It wraps **one** card at a time: `role` is `'first' | 'second' | null` and `onUnlink` is optional. With `role` null it renders a plain `View` around the children, so the React tree stays the same when a card is linked or unlinked. That matters because the workout cards keep unsaved draft rows and note text in local state, and wrapping two cards in a new parent would remount them and lose that text.
- **Bar:** with a role, the wrapper gets a 4 dp **blue** left bar (`borderLeftWidth: 4`, `borderLeftColor: colors.primary`) and `paddingLeft: spacing.sm`. The bars of the first and second wrapper touch, so they read as one frame from the header down to the bottom of the second card (no bar sticking out under it).
- **Keep the card width:** the wrapper also gets `marginLeft: -spacing.md`, so the bar sits in the screen's 16 dp side gutter (4 dp from the screen edge) and the paired cards stay exactly as wide as the others. At 375 px the workout set row is already tight (in the before shot the reps box is cut off), so the frame must not take 12 dp from it.
- **Header** (first wrapper only), one row above the first card, all in blue: `⛓ Superset` (`labelSmall`, `colors.primary`; contrast on grey `surface` is about 4.7:1), then ` · ` and a `TextLink` "Unlink" right after it, when `onUnlink` is given. On the summary there is no `onUnlink`, so the header is just `⛓ Superset`. TalkBack reads the label as "Superset", not the chain emoji.
- **Link placement ("⛓ Superset with next"):** the same on both screens: a `TextLink`, left-aligned, as the **last line inside the card**. It never goes in the card header, which is already full at 375 px (name + ↑ ↓ Remove in the editor, name + Swap + Remove in the workout).
  - Routine editor: under the rest line ("Uses your default rest (1:30)  + Rest time", or the Rest input when set).
  - Active workout: under "+ Add set".
  - Shown only when `canLink` (rule above). When it is hidden, the card looks exactly like today.
- **Unlink is not a delete:** a blue `TextLink`, not red, with no confirm. Linking again undoes it in one tap.

**States**
- Routine editor: link and Unlink change the draft only, at once, with no spinner. They are saved with Save Routine, like targets and rest.
- Active workout, while the write runs: the tapped link is `disabled` (no double tap). Success: `refresh()` and the frame appears or goes away. Error: alert "Could not link" / "Could not unlink", "Check your connection and try again.", and the screen stays as it was.
- Empty and loading: nothing new. A routine or workout with fewer than 2 cards never shows the link.

**Words**
- Link: `⛓ Superset with next`. TalkBack: "Superset {A} with {B}".
- Frame header: `⛓ Superset · Unlink`. TalkBack on Unlink: "Unlink {A} and {B}".
- Summary header: `⛓ Superset`.
- Errors: "Could not link" / "Could not unlink", with "Check your connection and try again."

## Acceptance criteria

- [ ] 0026 runs on the live database. Old routines and workouts show no frame and act as before.
- [ ] The link never shows on the last card, on either card of a pair, or on a card whose next card starts a pair.
- [ ] Routine: link A+B, save, reopen: the frame is still there. Duplicate keeps the pair.
- [ ] Routine: moving any card in or next to a pair breaks that pair. Removing B of A+B leaves A unpaired, and a newly added exercise is not paired with A.
- [ ] Starting a workout from that routine shows the A+B frame.
- [ ] Workout: ticking a set on A starts no rest bar. Ticking a set on B starts rest with B's rest time (B's own routine rest, or the default). With a ↓ row right below on B, no rest starts until the last step. A ↓ row on A never starts rest.
- [ ] Workout: link and Unlink work at once and still show after leaving and resuming the workout.
- [ ] Swap with no sets keeps the pair. Swap with sets: first card → `A · [A' + B]`, second card → `[X + A'] · A`.
- [ ] Removing the second card of a pair leaves the first card unpaired. Adding an exercise afterwards does not pair it.
- [ ] Linking while typing a set row on one of the cards keeps the typed numbers (no remount).
- [ ] The summary shows the same frame, with no Unlink.
- [ ] With no signal, link/unlink shows the "Could not …" alert and changes nothing.
- [ ] `npx tsc --noEmit`, `npx expo lint` and `npx jest` pass.

## Risk

🔴 changes existing: it changes the active workout card (rest timer rule, swap, remove), the routine editor's move and remove, the routine save, and starting a workout (shared `workouts.ts`).

## Needs from the user

- Paste `supabase/migrations/0026_supersets.sql` into the Supabase SQL editor **before** `eas update`. Without it, `saveTemplate` and `startWorkout` send an unknown column, and saving a routine or starting one from a routine fails. Pasting early is safe, because old app versions ignore the column.
- No new APK build.

## Out of scope

- Groups of 3 or more, auto-jumping or scrolling between the two cards, and supersets in the CSV export (Decisions).
- Moving a pair as one unit in the routine editor. A move breaks the pair, and the user links again.
- Reordering in the active workout. It doesn't exist today.
- Stopping a rest timer that is already running when a set on the first card is ticked.
- Offline link/unlink.
- Showing pairs anywhere else: the routine list, history, the exercise page, Progress.
- A separate tested `startsRest` helper. The rule is one inline condition and the click-through covers it.
- Cleaning up stray flags on save. `supersetRoles` already ignores them everywhere.
