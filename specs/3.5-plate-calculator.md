# 3.5 – Plate calculator

Source: GitHub issue jjerner/FitTracker#12, "[3.5] Plate calculator. Tap a weight → plates per side (like Strong)." HANDOVER.md line 267 (Strong idea, effort S).

## Goal

In an active workout on a barbell exercise, one tap shows which plates go on each side of the bar to reach a weight.

## What exists today

- `src/app/(tabs)/workouts/active.tsx` → `ExerciseCard`: table Set | Previous | kg | reps | ✓. Rows you haven't saved yet have a kg `TextInput`, so tapping the weight already opens the keyboard. That means the calculator needs its own button, not "tap the weight". The weight shown in grey comes from `suggestion(setNumber).a`.
- Units: kg only (`weightKg` everywhere, no lb anywhere in `src/`).
- Equipment data: `exercises.equipment` (`Exercise.equipment` in `src/types/domain.ts:75`). The built-in exercises use `'barbell' | 'dumbbell' | 'machine' | 'cable' | 'bodyweight' | null`. Custom exercises always have `null` (`CreateExerciseForm` has no equipment field).
- Modal pattern: `src/components/workouts/SwapExercisePicker.tsx` (`Modal` + `SafeAreaView`, Cancel in the header).
- Number parsing: `toNumberOrNull` in `src/lib/numbers.ts` (accepts a comma, e.g. "62,5").

## Proposed smallest version

- In the `ExerciseCard` header, next to "⇄ Swap", add a "Plates" link. It only shows when `logExercise.exercise.equipment === 'barbell'`.
- Tapping it opens a small modal. The modal has one kg input, already filled in with the weight of the first row you haven't saved yet: what you typed, or else the grey suggestion. Below the input, the plates per side for that weight are listed, e.g. "Per side: 20 + 10 + 2.5". You can change the number in the modal to try another weight. Nothing gets saved.
- Fixed setup: 20 kg bar. Plates in kg: 25, 20, 15, 10, 5, 2.5, 1.25, as many of each as needed. Strong uses the same default.
- Edge cases:
  - weight at or below 20 → "Just the bar".
  - weight that can't be hit exactly → show the closest load below it and "X kg can't be loaded exactly".
  - empty or not a number → no result.

## Files to touch

- `src/lib/plates.ts` (new): `platesPerSide(totalKg: number, barKg = 20, plates = [25, 20, 15, 10, 5, 2.5, 1.25]): { perSide: number[]; leftoverKg: number }`. Takes the biggest plate that fits each time. It counts in hundredths of a kg (integers) so float rounding errors can't creep in. With this plate set, taking the biggest plate first always gives the fewest plates.
- `src/lib/__tests__/plates.test.ts` (new): see the test plan.
- `src/components/workouts/PlateCalculator.tsx` (new): the modal with props `{ visible, initialKg, onClose }`. Same look as `SwapExercisePicker`, but a short sheet (`transparent` + `animationType="slide"`, or a full screen like Swap if that is simpler).
- `src/app/(tabs)/workouts/active.tsx`: one `platesOpen` state, the "Plates" link in the header (barbell only), and the `<PlateCalculator>` next to `<SwapExercisePicker>`. `initialKg` = `toNumberOrNull(drafts[0]?.a ?? '') ?? suggestion(doneSets.length + 1).a`.

## Reuse

- `toNumberOrNull` from `src/lib/numbers.ts` for the modal input.
- The `Modal` / header / `colors` pattern from `SwapExercisePicker.tsx`.
- The existing `swapText` style for the "Plates" link.

## Acceptance criteria

- [ ] "Plates" shows on barbell exercises only (e.g. Bench Press, Deadlift). It does not show on Dumbbell Curl, Leg Press, cardio, or custom exercises.
- [ ] Tapping it opens the modal with the first unsaved row's typed or suggested weight.
- [ ] 100 kg shows "20 + 20" per side. 60 shows "20". 62.5 shows "20 + 1.25". 140 shows "25 + 20 + 15".
- [ ] 20 or less shows "Just the bar".
- [ ] 101 shows 100 kg loaded and a 1 kg leftover note.
- [ ] Typing "62,5" works like "62.5".
- [ ] Closing the modal changes nothing in the workout. No sets are saved and the draft rows stay the same.
- [ ] `npx tsc --noEmit` and `npx expo lint` pass. `npx jest` passes.

## Needs from the user

None. JS only, ships with `eas update`. Answers to the open questions below are needed first.

## Open questions

1. **Bar weight:** fixed at 20 kg, or let the user change it? If they can change it: in the modal only (forgotten when it closes), or saved in settings (`src/lib/settings.ts`)? What about a 15 kg women's bar or an EZ bar?
2. **Which plates:** is the default kg set (25, 20, 15, 10, 5, 2.5, 1.25) fine, or should users set what their gym has (e.g. no 25s, or 0.5 plates)?
3. **Which exercises:** barbell only (`equipment === 'barbell'`)? Plate-loaded machines (Leg Press, Hack Squat) also take plates, but they have no bar weight and the data can't tell them apart from other machines. Custom exercises have no equipment, so they'd never get the button. Should they always get it, or should the custom exercise form get an equipment field (out of scope here)?
4. **Where to put it:** a "Plates" link in the exercise card header (proposed), or a small icon on each set row, or a long-press on the kg box? Long-press on a `TextInput` clashes with text selection, so it's not recommended.
5. **Picture or text:** plain text "20 + 10 + 2.5" (proposed), or coloured plate bars like Strong?

## Out of scope

- lb / unit switching (the app is kg-only).
- Saved custom bar or plate inventories (unless question 1 or 2 says otherwise).
- Writing the weight back into the set row from the modal.
- Dumbbell / machine math, warm-up set calculator.
- The calculator anywhere else (template editor, workout log, exercise detail).

## Decisions (2026-10-18)

- Bar starts at 20 kg and can be changed inside the popup (not saved). Plates 25/20/15/10/5/2.5/1.25 kg.
- "Plates" link only on built-in barbell exercises (equipment = 'barbell').
- Card-header link next to "⇄ Swap", plain text result ("20 + 10 + 2.5 per side"), leftover shown when not exact.
- **User wants a demo and a heavy review before shipping**: screenshots/recording of the flow + edge cases (just bar, leftover, decimal comma, changed bar) in the PR, and the user reviews it before merge.
