# 4.4 – Calorie/protein goal hit-streak on Home

Issue: jjerner/FitTracker#13. HANDOVER.md → Proposed roadmap, section 4 "Progress & motivation": "Calorie/protein goal hit-streak on Home (like the workout streak)." Effort S.

## Goal

Show "🎯 N days on target" on Home's "Today's food" card: how many days in a row you hit your calorie and protein goals. It should work like the "🔥 N weeks in a row" line on the "This week" card.

## Today

- `src/app/(tabs)/home.tsx:61-76` works out the workout streak inline. It counts weeks with at least one workout. The current week does not break the streak until it is over. The streak shows in the "This week" card header (`cardHeader` + `styles.streak`) only when it is above 0.
- `useDailyNutrition()` (`src/hooks/useProgress.ts:40`) already gets one row per logged day (calories, protein, carbs, fat) for the last year from the `daily_nutrition` view. Days with nothing logged are not in the list. The Progress tab uses it.
- `useNutritionGoals()` returns one current goal (or `null`). Goals have no history.

## Definition (proposed, see open questions)

- **Hit day** = calories within ±10 % of the calorie goal (inclusive) **and** protein ≥ the protein goal.
- **Empty day** (nothing logged, so no row) = a miss. It breaks the streak.
- **Today**: it does not break the streak until the day is over. If today is already a hit, it counts. If not, counting starts from yesterday. This is the same rule as the workout week.
- **Goal used**: every past day is checked against today's goal, because goals have no history.
- **No goals set** → no streak line.
- The line shows only when the streak is above 0 (same as workouts).

## Files to touch

- `src/lib/progress.ts`: add a pure function `goalStreak(days: DailyNutrition[], goals: NutritionGoals, today: string): number`. It checks the hit rule on each day and walks back one day at a time from today (or yesterday, if today is not a hit yet).
- `src/app/(tabs)/home.tsx`:
  - call `useDailyNutrition()`
  - add `['dailyNutrition']` to the existing `useFocusEffect` invalidation, because food is logged on the Food tab
  - compute `const foodStreak = goals && days ? goalStreak(days, goals, today) : 0`
  - wrap the "Today's food" title in a `cardHeader` row with `🎯 {n} {day|days} on target` on the right, using the existing `styles.streak`
- `src/lib/__tests__/progress.test.ts`: add tests for `goalStreak`.

## Reuse

- `useDailyNutrition` / `getDailyNutrition` and the `daily_nutrition` view. No new query and no new SQL.
- `addDays` in `home.tsx` for stepping back one day. Pass it in, or move it to `src/lib/dateUtils.ts` if `goalStreak` needs it there. That is a small move, not a new helper.
- `styles.cardHeader` and `styles.streak` (`colors.streak`) that are already in `home.tsx`.

## Acceptance criteria

- [ ] With goals set and a run of N days that are hits, ending yesterday or today, Home shows "🎯 N days on target" ("1 day" when N is 1) in the "Today's food" card header.
- [ ] A day under 90 % or over 110 % of the calorie goal breaks the streak. So does a day below the protein goal, or a day with nothing logged.
- [ ] Today that is not a hit yet (for example nothing logged this morning) does not reset the streak. Once today becomes a hit, the count goes up by 1.
- [ ] With no goals, or a streak of 0, there is no streak line.
- [ ] Log food, go back to Home, and the streak updates without restarting the app.
- [ ] Tapping the card still opens the diary.
- [ ] `npx tsc --noEmit` and `npx expo lint` are clean. The new jest tests pass.

## Test plan

- Unit tests for `goalStreak` in `src/lib/__tests__/progress.test.ts`:
  - 3 hit days ending yesterday, with today empty → 3
  - same, plus today is a hit → 4
  - a missing day in the middle → only counts back to the gap
  - one day at 111 % calories, or with protein 1 g short, breaks the streak. Days at exactly 90 % and exactly 110 % count.
  - an empty list → 0
- On web (test account from `.env.test.local`):
  1. Set goals. Log food for today that hits both goals. Home shows "🎯 1 day on target" (or more if earlier days in the test account are hits).
  2. Delete that food. The line goes away, or drops back to the count up to yesterday.
  3. Clear the goals. No line.
  4. Tap the card. The diary opens. Check the console for errors.
  - The web test only covers today, because the app has no way to log food on past days other than through the diary date picker. Use the date picker to log yesterday too, if you want to see a 2-day streak.
- Phone: nothing special. JS only.

## Open questions

1. What counts as a hit for calories: within ±10 %, a different window, or "at or under the goal"? (Under suits cutting, a window suits maintenance or bulking.)
2. Should a hit need both calories and protein, or should there be two separate streaks (one for calories, one for protein)?
3. Should an empty day (nothing logged) break the streak, or be skipped (no hit, but no break)?
4. Is the text "🎯 N days on target" and the place (header of the "Today's food" card) OK?
5. Is it OK to check past days against today's goal? If you change your goal, old days get judged again. Avoiding that would need goal history, which means SQL.

## Out of scope

- Goal history and a different goal per day (or 5.3 training vs rest days).
- Carbs, fat or fiber in the hit rule.
- A "best streak" record, a calendar of hit days, notifications or badges.
- Showing the streak on the Food or Progress tab.

## Decisions (PM, 2026-10-18)

1. One streak: a day is a hit when calories are within **±10 %** of the goal (inclusive) **and** protein ≥ goal. Text "🎯 N days on target" in the "Today's food" card header.
2. A day with nothing logged **breaks** the streak; today only counts once it is over.
3. Past days are judged against the **current** goal (no goal history) — accepted.
4. Checked: `daily_nutrition` groups by the stored `logged_date` column, so there is no server time-zone issue.
