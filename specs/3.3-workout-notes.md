# 3.3: Workout notes + per-exercise notes (issue #18)

## Goal

Two kinds of note. A **workout note**: a text box under the timer on the active workout screen, shown on the summary afterwards. An **exercise note** ("Seat at 4"): one per user per exercise. It shows under the exercise name in every workout until you change it, and on the exercise's detail page.

## Files to touch

- `supabase/migrations/0024_exercise_notes.sql` (new). Same style as `0010_tracked_exercises.sql`:
  ```sql
  -- 3.3: one sticky note per user per exercise ("Seat at 4"), shown in every workout.
  create table public.exercise_notes (
    user_id uuid not null references auth.users(id) on delete cascade,
    exercise_id uuid not null references public.exercises(id) on delete cascade,
    note text not null check (char_length(note) between 1 and 200),
    primary key (user_id, exercise_id)
  );

  alter table public.exercise_notes enable row level security;

  create policy "Users can manage own exercise notes"
    on public.exercise_notes for all
    using (user_id = auth.uid())
    with check (user_id = auth.uid());
  ```
  - The primary key is the unique (user_id, exercise_id). The single `for all` policy covers select, insert, update and delete of your own rows, as in 0010 and 0015.
  - Account deletion (0019): both foreign keys cascade. When `auth.users` is deleted, the user's notes go with it, and so do notes on the user's own exercises (`exercises.created_by` cascades too). Nothing blocks the delete, so `delete_my_account()` does not change.

- `src/lib/workouts.ts`:

## UX/UI

**Placement call: "+ Note" goes under the exercise name, not in the header.** At 375 px the card has about 319 px inside. Swap + Remove + "+ Note" with their gaps take about 190 px, which leaves the name about 125 px. "Front Squat" fits, but "Dumbbell Romanian Deadlift" or "Smith Machine Bench Press" would break into 3 lines, and that happens on every new card because Remove shows until the first set is done. Under the name there is one "note slot". It shows "+ Note", the note itself, or the edit box, always in the same place. The header stays as it is.

**Flow**
- Workout note: Active workout → type in "Workout note" → tap anywhere else (saves) → Finish → the summary shows "Note: …" under the date.
- Exercise note: card → "+ Note" → a box opens with the keyboard up → type → tap anywhere else (saves) → the slot shows "Note: Seat at 4". Tap the note → the box opens with the text filled in → edit or clear → tap anywhere else. A cleared note is deleted and "+ Note" comes back.
- Later workouts and the exercise detail page show the note read-only.

**Screens and parts** (nothing new)
- Active workout: `LabeledInput` (workout note, on the grey screen, between the clock/tip and the first card). In each `ExerciseCard`, the note slot: a plain `Pressable` with `swapText` ("+ Note") or `AppText small` ("Note: …"), or a `LabeledInput` while editing.
- Summary (`log/[logId]`): one `AppText small` line in `textSecondary` under the date.
- Exercise detail: one `AppText small` line at the top of the header `Card`, above the record tiles.
- No Save button. Leaving the box saves it, like sets save on tick. The note showing up in the slot is the "saved" feedback.

**States**
- Notes still loading: the slot is empty. It does not show "+ Note" first and then jump to the note.
- Notes failed to load (for example before 0024 is pasted): "+ Note" shows. Saving then gives the error alert.
- Saving: no spinner. The box stays until the save finishes, then turns into the note line.
- Save failed: alert "Could not save note" / "Check your connection and try again." The box stays open with the text kept.
- No note: summary and detail page show no line at all (no "No note" text).

**Words**
- "Workout note" (box label, no placeholder)
- "+ Note" (TalkBack: "Add note to Back Squat")
- "Note" (box label), placeholder "e.g. Seat at 4"
- "Note: Seat at 4" (TalkBack hint: "Edit note")
- Summary / detail page: "Note: …"

## Offline rule

Note saves work online only, like adding, swapping or removing an exercise. They do not go into `pendingSets`. If a save fails, the alert shows and the typed text stays on screen, so leaving the box again (or Finish, for the workout note) tries again. Sets keep working offline exactly as before.

## Acceptance criteria

- [ ] With 0024 pasted, a "Workout note" box shows under the timer (and under the tip box when it is open). Text typed there and left is saved to `workout_logs.notes`. It is still there after leaving and resuming the workout.
- [ ] If you type in the workout note and tap Finish without leaving the box first, the note still shows on the summary as "Note: …".
- [ ] If you clear the workout note and leave the box, `notes` becomes null and the summary shows no note line.
- [ ] An exercise with no note shows "+ Note" under its name. Tapping it opens a box, and leaving the box saves the note. The card then shows "Note: Seat at 4" under the name.
- [ ] Tapping the note opens it for editing with the text filled in. Changing it and leaving the box saves it. Clearing it and leaving the box deletes the note, and "+ Note" comes back.
- [ ] The note shows on that exercise in every later workout, in any routine, and on the exercise detail page. Another account never sees it.
- [ ] After a swap, the card shows the new exercise's note, or "+ Note" if it has none.
- [ ] If you go offline and save a note, the "Could not save note" alert shows, the text is still on screen, and ticking sets still queues them as before.
- [ ] The DB rejects a 201-character note. The box stops you at 200 (500 for the workout note).
- [ ] Deleting an account that has exercise notes, including notes on its own custom exercises, still works.
- [ ] Sets, rest timer, swap, remove, the tip box and the CSV export work as before. The export has no notes.
- [ ] Every new tap target is at least 48 dp and has a TalkBack label. There is no raw hex or `fontSize` in the new code. `npx tsc --noEmit`, `npx expo lint` and `npm test` pass.

## Test plan

- **Unit** (`src/lib/__tests__/exerciseNotes.test.ts`, with Supabase mocked as in `upsertOffFood.test.ts`):
  - `saveExerciseNote` with `'  Seat at 4 '` upserts `note: 'Seat at 4'` with `onConflict: 'user_id,exercise_id'`.
  - `saveExerciseNote` with `'   '` deletes, filtered on `user_id` and `exercise_id`, and doesn't upsert.
  - `saveWorkoutNote` with `'  '` updates `notes: null`. With `' ok '` it updates `notes: 'ok'`.
  - `getExerciseNotes` maps rows to `{ [exercise_id]: note }`.
  - A Supabase error makes each save throw.
- **Web** (the user pastes 0024 first; `npx expo start --web --port 8081`; log in with the test account from `.env.test.local`):
  1. Start an empty workout and add Back Squat. Type a workout note, click outside the box, then reload. The note is still there.
  2. On Back Squat, tap "+ Note", type "Seat at 4" and click outside. "Note: Seat at 4" shows. Tap it, change the text, click outside, and reload. The new text shows.
  3. Edit the workout note and click Finish straight away. The summary shows the new note.
  4. Start another workout and add Back Squat. The note shows. Open Back Squat's detail page. The note shows there too.
  5. Clear the exercise note. "+ Note" comes back. Swap to another exercise. Its own note (or "+ Note") shows.
  6. In DevTools, go offline and edit a note. The alert shows and the text stays. Tick a set: it is queued as before. Go back online.
  7. Watch the console for errors. Discard or delete the test workouts.
- **Phone** (one `phone-test` issue): type an exercise note and the workout note, then tap Finish while the keyboard is still open. Both notes are saved. Also check TalkBack on "+ Note" and on the note line.

## Out of scope

- One-off exercise notes for a single session, notes on routines, and notes in the CSV export (per the Decisions).
- Showing exercise notes on the workout summary, or editing any note on the summary or detail page (read-only there).
- Saving notes offline (no note queue). The online-only rule above covers it.
- A DB length limit on `workout_logs.notes` (no SQL for that part, per the Decisions; the box limits it to 500).
- Notes in the workout history list, and an `updated_at` / `created_at` column on `exercise_notes` (nothing reads them).
