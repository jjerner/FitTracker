# 5.5 – Export my data (CSV)

Issue: jjerner/FitTracker#15. Label `apk-build`. Why: GDPR right to data portability, and the app-store privacy questions.

## Goal

From Profile → Account, a signed-in user can export their food log, workouts and weights as three separate CSV files. On the phone the file goes to the share sheet. On web it downloads.

## Data (looked up in the migrations)

| Export | Source | Columns → CSV |
|---|---|---|
| Food log | `food_log_entries` (0002, +`serving_g` 0009, `food_id` nullable 0011) with `foods(serving_size_g)` | `logged_date`, `meal_type`, `food_name`, amount (g), `calories_kcal`, `protein_g`, `carbs_g`, `fat_g`, `fiber_g` |
| Workouts | `workout_logs` (0004) → `workout_log_exercises(position, exercises(name), workout_log_sets(set_number, reps, weight_kg, duration_s, distance_m, set_type))` (0004, `set_type` 0017) | local date of `started_at` (`localDateOf`), `workout_logs.name`, `exercises.name`, `set_number`, `reps`, `weight_kg`, `duration_s`, `distance_m / 1000` (km), `set_type = 'warmup'` → `yes`/`no` |
| Weight | `body_weights` (0005) | `logged_date`, `weight_kg` |

- **Amount (g)** uses the same rule as `entryNutrition` (`src/lib/foods.ts:304`): `quantity_unit = 'g'` → `quantity`. `'serving'` → `quantity × (serving_g ?? foods.serving_size_g ?? 100)`. Quick-add entries (`food_id` null) have no grams → empty cell.
- **Numbers:** kcal rounded to whole numbers. Grams and macros to 1 decimal. Reps, set number, weights and duration as stored. Distance is `distance_m / 1000`. A null value gives an empty cell.
- **Header rows:** `Date,Meal,Food,Amount (g),kcal,Protein (g),Carbs (g),Fat (g),Fiber (g)` / `Date,Workout,Exercise,Set,Reps,Weight (kg),Duration (s),Distance (km),Warm-up` / `Date,Weight (kg)`. Meal is the raw value (`breakfast`, ...).
- **Unfinished workouts** (`completed_at` null, e.g. one in progress) are included. No filter on `completed_at`.
- **Order:** food by `logged_date`, `logged_at`, `id`. Weight by `logged_date`. Workouts by `started_at`, `id`, then exercises by `position` and sets by `set_number` (sorted in JS, the same way `getWorkoutLog` does, `src/lib/workouts.ts:261`).
- **Every query filters `.eq('user_id', userId)`** (food, weight, `workout_logs`), on top of RLS.
- **Paging:** Supabase caps each request at 1000 rows (PROJECT_NOTES, "Supabase caps a request at 1000 rows"). Read with `.range(from, from + 999)` in a loop until a page comes back with fewer than 1000 rows. The order above ends in a unique column, so pages don't overlap. For workouts the page counts `workout_logs` rows. The embedded exercises and sets come back whole (the cap only applies to the top-level rows).

## CSV format

One pure function, `toCsv(rows: (string | number | null)[][]): string`:
- A cell that contains `"`, `,`, `\r` or `\n` is wrapped in `"…"`, with every `"` doubled (RFC 4180). Other cells stay as they are. `null` gives an empty cell.
- Rows are joined with `\r\n`.
- The output starts with a UTF-8 BOM (`﻿`), so Excel shows å/ä/ö in Livsmedelsverket food names correctly.
- Comma separator, dot decimals.

## Files to touch

1. **`package.json`**: `npx expo install expo-sharing expo-file-system`. `expo-file-system` today is only nested under `expo/node_modules`, so it must become a direct dependency before the app can import it.
2. **New `src/lib/exportData.ts`**:
   - `toCsv` (above).
   - `foodLogCsv(userId)`, `workoutsCsv(userId)`, `weightsCsv(userId)`: each fetches all pages, maps the rows to the columns above and returns `toCsv([header, ...rows])`.
   - `shareCsv(fileName, csv)`:
     - **Native:** `const file = new File(Paths.cache, fileName); file.create({ overwrite: true }); file.write(csv);` then `Sharing.shareAsync(file.uri, { mimeType: 'text/csv', dialogTitle: fileName })`. This is the v57 object API from `expo-file-system` (`File`, `Paths.cache`), not `/legacy`. If `await Sharing.isAvailableAsync()` is false, throw so the screen shows the error alert.
     - **Web (`Platform.OS === 'web'`):** plain download. `new Blob([csv], { type: 'text/csv' })` → `URL.createObjectURL` → a temporary `<a download={fileName}>` → `click()` → `revokeObjectURL`. The v57 `expo-file-system` is a stub on web (`ExpoFileSystem.web.d.ts` has empty classes), so the native path can't run there.
   - File names: `plucky-food-log-YYYY-MM-DD.csv`, `plucky-workouts-YYYY-MM-DD.csv`, `plucky-weight-YYYY-MM-DD.csv` (date from `todayLocalDate()`).
3. **New `src/app/(tabs)/profile/export.tsx`** ("Export my data" screen): `ScrollView` with `settingsStyles`, one `SettingsGroup` with three `SettingsRow`s: **Food log (CSV)** (`{ ios: 'fork.knife', android: 'restaurant' }`), **Workouts (CSV)** (`{ ios: 'dumbbell.fill', android: 'fitness_center' }`), **Weight (CSV)** (`{ ios: 'scalemass', android: 'monitor_weight' }`).
   - `const [busy, setBusy] = useState<'food' | 'workouts' | 'weight' | null>(null)`.
   - The tapped row shows `<ActivityIndicator color={colors.primary} accessibilityLabel="Exporting" />` as its `children`. While anything is busy, every row gets `onPress={undefined}`, so a second tap can't start a second export. `SettingsRow` then renders a plain `View`. No change to `SettingsRow`.
   - Errors: `Alert.alert("Couldn't export", 'Check your connection and try again.')`, the same wording as the rest of the app. `finally` → `setBusy(null)`.
4. **`src/app/(tabs)/profile/_layout.tsx`**: add `<Stack.Screen name="export" options={{ title: 'Export my data' }} />`.
5. **`src/app/(tabs)/profile/account.tsx`**: in the first group, under Change password, add `<SettingsRow icon={{ ios: 'square.and.arrow.up', android: 'download' }} label="Export my data" chevron onPress={() => router.push('/(tabs)/profile/export')} />`.
6. **New `src/lib/__tests__/exportData.test.ts`** (see Test plan).

## UX/UI

Design note (approved mockup; `docs/design-system.md` rules). Android only, so the Material icon name is the one that counts.

**Flow:** Profile → Account → tap **Export my data** → "Export my data" screen → tap a row → spinner on that row → share sheet (phone) / file downloads (web) → back on the same screen, row normal again. Back arrow in the header returns to Account.

**Screens and parts:**
- **Account (changed):** one new `SettingsRow` in the first `SettingsGroup`, under Change password. Icon `download`, `chevron` (it opens a screen). Nothing else moves.
- **Export my data (new):** stack header title "Export my data" (from `_layout.tsx`, no in-screen title). `ScrollView` + `settingsStyles`, one `SettingsGroup`, three `SettingsRow`s. Icons match the tab bar: `restaurant` (Food tab), `fitness_center` (Workouts tab), `monitor_weight`. **No chevron** on these rows: they act, they don't open a screen (same as Sign out).
- Nothing new in the design system. No change to `SettingsRow`.

**States:**
| State | What the user sees |
|---|---|
| Idle | Three rows, all tappable, pressed look from `SettingsRow`. |
| Working | Tapped row: `ActivityIndicator` (`colors.primary`) on the right, where a chevron would sit. All three rows ignore taps (rendered as plain `View`). Other rows look the same, no dimming (that would need a `SettingsRow` change, and it lasts a second or two). |
| Success | Phone: Android share sheet with the `.csv`. Web: browser download. No extra toast/message; the sheet or download *is* the feedback. Row goes back to idle when the sheet closes. |
| Share sheet cancelled | Nothing shown, row back to idle. Not an error. |
| Error | Alert, row back to idle: title **Couldn't export**, message **Check your connection and try again.** (one OK button). Web shows no alert (known, see Out of scope). |
| Empty (no data) | No special state: the file has only the header row (approved). |

**Words:**
- Account row: **Export my data**
- Screen title: **Export my data**
- Rows: **Food log (CSV)**, **Workouts (CSV)**, **Weight (CSV)**
- Error alert: **Couldn't export** / **Check your connection and try again.**
- File names: `plucky-food-log-YYYY-MM-DD.csv`, `plucky-workouts-YYYY-MM-DD.csv`, `plucky-weight-YYYY-MM-DD.csv`

**Accessibility:**
- Rows: `SettingsRow` already gives role "button" and the row text as the TalkBack label ("Food log (CSV), button"). Rows are 56 dp tall (min 48 met).
- Spinner: `<ActivityIndicator color={colors.primary} accessibilityLabel="Exporting" />`, so TalkBack has something to say while the row is busy (the row loses its button role while busy).
- Text scales with the font setting; labels wrap (`rowText` is `flex: 1`).
- No hex, no `fontSize`, no off-scale spacing: everything comes from `SettingsList` and `colors`.

## Acceptance criteria

- [ ] Account shows "Export my data" (chevron) directly under "Change password". It opens a screen titled "Export my data" with three rows.
- [ ] Tapping a row shows a spinner on that row. While it runs, other taps do nothing. Afterwards the share sheet opens (phone) or a `.csv` file downloads (web).
- [ ] Each file has the header row and columns listed above, one row per food entry / set / weight, for the signed-in user only.
- [ ] A cardio set shows its duration in seconds and its distance in km (e.g. `distance_m` 5000 → `5`).
- [ ] An unfinished workout (`completed_at` null) is in the workouts file.
- [ ] A food name with a comma, a quote or a line break stays one cell when the file is opened in Google Sheets or Excel. å/ä/ö show correctly in Excel.
- [ ] A serving entry shows grams (`quantity × serving grams`). A quick-add entry has an empty amount.
- [ ] A user with more than 1000 rows of one type gets every row (no cut-off at 1000).
- [ ] A user with no data gets a file with only the header row.
- [ ] A failed request shows the "Couldn't export" alert, and the row goes back to normal.
- [ ] `npx tsc --noEmit`, `npx expo lint` and `npx jest` pass.

## Test plan

- **Unit (`exportData.test.ts`; mock `../supabase`, `expo-file-system` and `expo-sharing` the way the other lib tests do):**
  - `toCsv`: a plain cell stays as it is. A comma, a `"` (doubled), `\n` and `\r\n` each get quoted. `null` → empty. Numbers. The BOM comes first, rows are joined by `\r\n`.
  - Food amount: `g` entry, `serving` entry with `serving_g`, `serving` entry without `serving_g` (falls back to `foods.serving_size_g`), quick-add (`foods` null) → empty. Test it through the row-mapping function, so keep that function exported.
  - Workout set row: a cardio set (`duration_s` 1800, `distance_m` 5000) → `1800` and `5`. A strength set (null duration/distance) → empty cells. Through the exported row-mapping function.
  - Paging: mock `range` to return 1000 rows, then 3 rows. The function returns 1003 rows and calls `range(0, 999)` and then `range(1000, 1999)`.
- **Web** (`npx expo start --web --port 8081`, test account from `.env.test.local`): Profile → Account → Export my data. Tap each of the three rows, check that a file downloads, open it and check the headers, a few rows and the dates. Watch the console for errors. (On web, `Alert.alert` shows nothing, so check the error path on the phone.)
- **Phone (`phone-test` issue, needs the new APK):** each row opens the Android share sheet with a `.csv` file. Save it to Drive or send it by mail and open it in Sheets. Turn on airplane mode, tap a row → "Couldn't export" alert, and the spinner goes away.

## Risk

🟢 add-on. It adds one row, one new screen and a new lib file. It reads data only, and no existing screen or shared code changes how it works.

## Needs from the user

- **A new APK build** (`expo-sharing` is native; `apk-build` label). With the `fingerprint` runtime, an `eas update` sent after this merge only reaches the new APK. Phones on build 2 get no further updates until they install build 3. So: build the APK, have the testers install it, then ship. After the build, paste the `app_releases` row as usual so build-2 phones see "New version available".
- **Shipping: the PR stays open (not merged) until the user is ready to build the new APK.** Merging it earlier would put the fingerprint change on master and cut build-2 phones off from every later `eas update`.
- No SQL. No migration.

## Out of scope

- A single "export everything" file, ZIP, or JSON export.
- Goals, routines/templates, custom foods, saved meals, servings, favourites, profile/body details. Only the three approved types.
- Date-range picking, choosing columns, and semicolon/Swedish-Excel separators.
- An "Nothing to export yet" message (an empty file with only the header is fine).
- Saved-meal group names, logged time-of-day, sugar/sodium.
- A web-only error dialog (`window.alert`): the app uses `Alert.alert` everywhere, so web shows no error popup here either.
- Changes to `SettingsRow` (no `loading` prop; the spinner goes in through `children`).
