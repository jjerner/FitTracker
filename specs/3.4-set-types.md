# 3.4 – Set types (warm-up / drop set / failure)

Source: GitHub issue jjerner/FitTracker#20 (label `sql`), HANDOVER.md → Proposed roadmap → 3.4: "Set types: warm-up / drop set / failure; warm-ups excluded from PRs and volume."

## Goal

Each strength set can be marked as a warm-up, a drop set, or a failure set. Warm-ups are left out of PRs, the estimated 1RM, charts, and volume. Drop and failure sets count like normal sets and only get a label.

## Design

- One new column on `workout_log_sets`: `set_type`, which is `normal` (the default) or `warmup`, `drop` or `failure`. Every existing set becomes `normal`, so old history does not change.
- **Active workout:** tap the "Set" cell of a row that is not ticked yet. Each tap moves to the next type: normal → W → D → F → normal. A normal row shows its number, the others show the letter. The type is saved together with the set when you tick ✓. Strength exercises only; on cardio the cell can't be tapped.
- To change the type of a ticked set in the active workout, un-tick it. The draft row it goes back to keeps its type, so you change the type and tick it again. The set is not updated in place.
- **Summary (`log/[logId]`):** the edit popup gets four chips (Normal / Warm-up / Drop / Failure) for strength sets. They save through `updateSet`.
- **Leaving warm-ups out happens in one place.** `records.ts` gets `workingSets(sets)`, which returns the sets that are not warm-ups. `bestOf`, `heaviestSet` and `findNewRecords` use it. That covers the 🏆 in the active workout, the summary highlights, the exercise page records and chart, and the Progress tab "tracked" stats. Volume on the summary uses it too.
- `formatSet` adds the label (`60 kg × 10 · Warm-up`), so the summary list and the exercise history list both show it.

## Files to touch

- `supabase/migrations/0017_set_types.sql` (new)
  - `alter table public.workout_log_sets add column set_type text not null default 'normal' check (set_type in ('normal', 'warmup', 'drop', 'failure'));`
  - The RLS policy on `workout_log_sets` is `for all` and limited to the owner (0004), so no policy change is needed.
- `src/types/domain.ts`: `export type SetType = 'normal' | 'warmup' | 'drop' | 'failure';` and `WorkoutSet` gets `setType: SetType`.
- `src/lib/workouts.ts`
  - `mapSetRow`: `setType: row.set_type ?? 'normal'`.
  - `addSet`: takes `setType` and writes `set_type`.
  - `updateSet`: `values` gets `setType` and writes `set_type`.
  - `formatSet`: when the type is not `normal`, add ` · Warm-up` / ` · Drop set` / ` · Failure`, for strength sets and cardio sets alike.
- `src/lib/pendingSets.ts`
  - `PendingSet` gets `setType: SetType`.
  - `doFlush` writes `set_type: set.setType ?? 'normal'`. Sets queued by the old app version have no `setType`, and those must still be sent.
- `src/lib/records.ts`
  - New `export function workingSets(sets: WorkoutSet[]) { return sets.filter((s) => s.setType !== 'warmup'); }`.
  - `bestOf`: reduce over `workingSets(sets)`.
  - `heaviestSet`: loop over `workingSets(session.sets)`.
  - `findNewRecords`: if no earlier session has a working set, there is no record. Today the check is `earlier.length === 0`. Change it to `!earlier.some((s) => workingSets(s.sets).length > 0)`. Without this, the first working set after a warm-up-only session would be called a record.
- `src/app/(tabs)/workouts/active.tsx`
  - `DraftRow` gets `type: SetType`. `newRow(a, b, type = 'normal')`.
  - The Set cell of a draft row becomes a `Pressable` (strength only) that cycles the type through `updateDraft`. It shows the number when the type is `normal`, otherwise `W` / `D` / `F`. It needs `accessibilityLabel` and `accessibilityHint` (for example "Set type: warm-up. Tap to change.").
  - Ticked rows show the same letter, but tapping it does nothing.
  - `handleDone`: put `setType: isCardio ? 'normal' : draft.type` in the payload. It goes to both `addSet` and `queueSet`.
  - `handleUndo`: `newRow(a, b, set.setType)`.
  - "+ Add set" copies a, b and the type of the last row.
  - The pending-to-`WorkoutSet` mapping (around line 146) adds `setType: p.setType ?? 'normal'`.
- `src/app/(tabs)/workouts/log/[logId].tsx`
  - `logVolume` sums over `workingSets(e.sets)`.
  - The edit popup state gets `type`. `openEdit` sets it from `set.setType`. For strength sets there is a chip row; reuse the chip styles from `CreateExerciseForm`, copied in locally the same way. `handleSaveSet` sends `setType` (always `'normal'` for cardio).
- `src/lib/__tests__/records.test.ts`: the `session()` fixture gets `setType` (default `'normal'`), plus the new tests below.

## Reuse

- The `workout_log_sets` table, `addSet` / `updateSet` / the offline queue, and `toNumberOrNull`.
- `bestOf` / `heaviestSet` / `findNewRecords` in `records.ts`. Filter inside them; don't add new record functions.
- The chip styles from `src/components/workouts/CreateExerciseForm.tsx`, the edit popup in `log/[logId].tsx`, and the theme colours (`colors.warning` for the letter, as for `recordText`).
- No new dependency, and no native code.

## Acceptance criteria

- [ ] Migration `0017` adds `workout_log_sets.set_type` (default `normal`, checked to the 4 values). Old workouts look and add up the same as before.
- [ ] Active workout, strength exercise: tapping the Set cell of an unticked row goes 1 → W → D → F → 1. Ticking saves that type. Cardio rows can't be tapped.
- [ ] A warm-up set with a weight above your best does **not** show 🏆, not in the active workout and not on the summary. A drop set or failure set that beats your best **does**.
- [ ] Summary volume (and "vs last time") leaves warm-ups out.
- [ ] The exercise page "Heaviest weight", "Best est. 1RM" and the chart, and the Progress tab tracked current/PR, all leave warm-ups out.
- [ ] The summary and the exercise history list show "· Warm-up" / "· Drop set" / "· Failure" after those sets.
- [ ] Summary edit popup: changing a set's type and saving updates the label, the volume and the highlights.
- [ ] Un-ticking a set keeps its type in the draft row. "+ Add set" copies the last row's type.
- [ ] Offline: a set ticked with no signal keeps its type once it is sent. A set queued by the old app version (no `setType`) is still sent, as `normal`.
- [ ] `npx tsc --noEmit`, `npx expo lint` and `npx jest` pass.

## Test plan

- Unit tests in `src/lib/__tests__/records.test.ts`:
  - `bestOf` ignores a heavier warm-up and still counts drop and failure sets.
  - `trackedStats`: a session whose heaviest set is a warm-up uses the heaviest working set. A session with only warm-ups gives no lift.
  - `findNewRecords`: earlier sessions with only warm-ups give no record. A warm-up above the earlier best gives no record. A failure set above the earlier best gives a record.
- Web click-through with the test account from `.env.test.local`, after the user has run the SQL:
  1. Start a workout with a strength exercise that already has history. Tap the Set cell of row 1 → W. Enter a weight above the PR and tick it. No 🏆 shows.
  2. Row 2: leave it normal, enter a normal weight, tick it. Row 3: set it to F, enter a weight above the PR, tick it. 🏆 shows.
  3. Un-tick the warm-up. The row comes back as W with its numbers. Tick it again.
  4. Add a cardio exercise and check its Set cell does nothing.
  5. Finish. On the summary, the warm-up shows "· Warm-up", volume leaves it out, and the highlights name the failure set.
  6. Edit the warm-up → Normal → Save. The volume goes up, and the highlight may change.
  7. Open the exercise page and the Progress tab, and check the warm-up does not drive the records or the chart.
  8. Check the console for errors.
- Phone list in HANDOVER: tick a W set in flight mode, turn signal back on, and check it shows as a warm-up on the summary.

## Needs from the user

- Paste `supabase/migrations/0017_set_types.sql` into the Supabase SQL editor **before** `eas update` (label `sql`). Without the column, every new set fails to save and sits in the offline queue.
- No new APK build; this ships as JS via `eas update`.
- Answers to the open questions below.

## Open questions

1. **Sets count on the summary:** should the "Sets" number count warm-ups? This spec counts every set, as today.
2. **Numbering:** this spec shows `W` / `D` / `F` in place of the number and keeps the other rows numbered by position (so after a warm-up the next set is "2"). Strong numbers only the working sets ("W, 1, 2"). Which do you want?
3. **How you pick a type:** tap-to-cycle on the Set cell (smallest), or tap → a small menu? And is it OK that a ticked set in the active workout changes type only by un-ticking it (or on the summary afterwards)?
4. **Migration number:** roadmap item 1.12 plans to use `0017` for `app_releases`. This spec takes `0017` because it is the next free number, and 1.12 would move to `0018`. OK?

## Out of scope

- Set types on cardio sets.
- Warm-up targets in routines (templates), and auto-generated warm-up sets.
- Matching the "Previous" column and the grey suggestions by set type. They still match by position, as today.
- Changing the type of a ticked set in place in the active workout.
- Showing set types in CSV export (5.5 doesn't exist yet) or in weekly sets per muscle (4.2).

## Decisions (PM, 2026-10-18)

These override the proposal above where they differ.

1. **Warm-up sets only.** No failure type. Drop sets are a different thing (one set with weight steps: 50 kg × 2 → 40 × 3 → 30 × 3 = 1 set) and moved to their own ticket, jjerner/FitTracker#44 (3.4b). Issue #20 renamed "Warm-up sets".
   - DB: keep it minimal and future-proof — `set_type text not null default 'normal' check (set_type in ('normal','warmup'))` (3.4b can widen the check later). Migration number assigned at build time.
   - Tap cycles **1 ↔ W** only. Summary edit popup: two chips (Normal / Warm-up).
2. Summary "Sets" count **includes** warm-ups; volume and records exclude them.
3. **Strong-style numbering**: W, W, 1, 2 (only working sets get numbers).
4. Tap the set number to toggle; a ticked set changes only after unticking it, or on the summary screen.
