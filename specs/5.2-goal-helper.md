# 5.2 – Goal helper (suggest calories/macros)

Issue: jjerner/FitTracker#23 (`needs-decision`). HANDOVER.md → Proposed roadmap → section 5, row 5.2: "suggest calories/macros from weight, height, age, activity and goal (lose/keep/gain). `profiles` already has `height_cm`, `sex`, `date_of_birth` (user earlier said they only wanted name in Profile – ask before adding these fields to the UI)."

## Goal

On the Nutrition Goals screen, a "Suggest goals for me" helper asks for a few body facts, works out protein/carbs/fat, and fills them into the form. The user checks the numbers and taps the normal Save button. Profile stays name-only.

## Today

- `src/app/(tabs)/profile/goals.tsx`: three text boxes (protein, carbs, fat). Calories are calculated from them (P×4 + C×4 + F×9) and are not typed. "Save Goals" calls `useNutritionGoals().saveGoals` and goes back. The screen is a plain `View`, not a `ScrollView`.
- `src/hooks/useNutritionGoals.ts`: reads and saves `nutrition_goals`. No change needed.
- `src/hooks/useProgress.ts` → `useBodyWeights()`: the last year of weigh-ins. `src/lib/progress.ts` → `weightTrend()`: a 7-day average per weigh-in.
- `supabase/migrations/0001_profiles.sql`: `profiles` has `sex`, `height_cm` and `date_of_birth`. Nothing in the app reads or writes them (`src/lib/profile.ts` only touches `display_name`).

## Proposal (smallest version)

**Where the inputs live:** only inside the helper, and they are not saved (see open question 1). Weight is filled in from the newest 7-day trend value (`weightTrend(weights).at(-1)`), and the user can change it. Age is typed in years, not a date of birth.

**Formula** (pure function, `src/lib/goalHelper.ts`):

1. BMR (Mifflin-St Jeor) = 10·kg + 6.25·cm − 5·age, then **+5** for male or **−161** for female.
2. Daily burn (TDEE) = BMR × activity factor: Sedentary 1.2 · Light (1–3 days/week) 1.375 · Moderate (3–5) 1.55 · Very active (6–7) 1.725 · Extra (physical job + training) 1.9.
3. Target kcal = TDEE + goal change: Lose **−500** · Keep **0** · Gain **+300** (amounts: open question 2). Never below a floor (open question 4).
4. Protein = **1.8 g/kg** body weight (open question 3).
5. Fat = **25 %** of target kcal ÷ 9.
6. Carbs = what's left: (target − protein×4 − fat×9) ÷ 4, never below 0.
7. Round each macro to the nearest 5 g. The form then shows calories as the macro sum, as it does today. Because of the rounding, this can be a few kcal off the target. That is fine.

```ts
export type GoalHelperInput = {
  sex: 'male' | 'female';
  ageYears: number;
  heightCm: number;
  weightKg: number;
  activityFactor: number;
  goal: 'lose' | 'keep' | 'gain';
};
export function suggestGoals(input: GoalHelperInput): { proteinG: number; carbsG: number; fatG: number };
```

**Flow on the Goals screen:**

```
[ Suggest goals for me ▸ ]        <- tap to open/close
  Sex       (Male) (Female)
  Age       [ 34 ]
  Height cm [ 180 ]
  Weight kg [ 82,4 ]              <- from the weight trend, editable
  Activity  (Sedentary)(Light)(Moderate)(Very)(Extra)
  Goal      (Lose)(Keep)(Gain)
  [ Fill in suggestion ]
  Estimate only, not medical advice.
Protein (g) [ 150 ]   <- filled in, user can still edit
Carbs (g)   [ 230 ]
Fat (g)     [ 70 ]
Daily Calories 2 150 kcal
[ Save Goals ]
```

"Fill in suggestion" only sets the three text boxes and closes the helper. Nothing is saved until the user taps Save Goals.

## Open questions

1. **Inputs: remember or not?** (a) Ask every time and save nothing (proposed; weight is prefilled anyway); (b) save sex/height/birth date to the existing `profiles` columns but keep them out of the Profile screen (they show only in the helper); (c) also show them in Profile (the user said earlier: name only).
2. **Goal change:** fixed −500 / 0 / +300 kcal, or a percentage (e.g. −20 % / 0 / +10 %), or let the user pick a pace (e.g. 0.25 / 0.5 kg per week)?
3. **Protein:** 1.8 g/kg for every goal, or a different amount per goal (e.g. 2.0 when losing, 1.6 when keeping/gaining)?
4. **Calorie floor:** clamp at 1 200 kcal (female) / 1 500 kcal (male), or no floor and only a warning?
5. **Sex options:** only Male/Female (the formula needs one), or also "Prefer not to say" using the average of the two (−78)?
6. **Fat share:** 25 % of kcal, or something else (e.g. 30 %)?

## Decisions (PM, 2026-10-19)

These override the proposal and open questions above. Ticket: jjerner/FitTracker#53 (GOALS-1, step 1 of 6 of #43).

1. **Remember inputs, hidden:** sex, height and birth date are saved to the existing `profiles` columns (`sex`, `height_cm`, `date_of_birth`; no SQL). They show only inside the helper, prefilled next time. The Profile screen stays name-only. Age is asked as **birth year** and saved as `<year>-07-01` (mid-year, so age is off by at most half a year). Weight is not saved here; it is prefilled from the 7-day trend as before.
2. **Lose/keep/gain is a pace:** chips Lose 0.75 / 0.5 / 0.25 kg per week, Keep, Gain 0.25 kg per week. kcal change = pace × 7 700 / 7 (Lose 0.5 → −550 kcal). Same constant as the adaptive goal (#54).
3. **Protein:** a stepper in g/kg body weight, preloaded by goal: **2.0** when losing, **1.6** when keeping or gaining. Range 1.2–2.6, step 0.1. Changing the goal reloads the suggestion.
4. **Fat:** a stepper in g/kg, range **0.5–0.8**, step 0.1, preloaded by goal: **0.6** when losing (keeps fat near 25 % of kcal at low calories), **0.8** when keeping or gaining. Carbs = what's left, never below 0.
   - Research basis: ISSN protein stand (1.4–2.0 g/kg for most exercisers, more in a deficit), Helms et al. 2014 (2.3–3.1 g/kg lean mass in a deficit ≈ 2.0 g/kg body weight; fat 15–30 % of kcal).
5. **Floor:** never suggest below 1 200 kcal (female) / 1 500 kcal (male). When clamped, a short line says so and suggests a slower pace.
6. **Sex:** Male / Female only, labelled "Sex (for the formula)".
7. **Goals screen shows each macro three ways:** grams (the input), % of calories, and g/kg body weight (from the newest 7-day trend; the g/kg part is hidden when there are no weigh-ins). This applies to the normal form, not only the helper.
8. **Shared macro rule:** put the split in one pure function in `src/lib/goalHelper.ts`, e.g. `macrosFor({ kcal, weightKg, proteinPerKg, fatPerKg })` plus the per-goal defaults, so the adaptive card (#54) reuses it. Test it.
9. Saving the pace/direction is step 3 (#55), not here.
